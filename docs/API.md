# carry os API

> **Status:** only the health endpoint is implemented. Product endpoint
> contracts are **TBD** and must be agreed before implementation.

## 1. Conventions

- Protocol: REST over HTTP
- API prefix: `/api`
- Local base URL: `http://localhost:3001/api`
- Documentation: Swagger UI at `http://localhost:3001/api/docs`
- OpenAPI JSON: `http://localhost:3001/api/docs-json` (generated by NestJS
  Swagger at runtime)
- Request/response validation: shared contracts from `packages/shared` where
  practical
- Authentication: not implemented
- Versioning: **TBD**
- Error envelope: **TBD**
- Pagination: **TBD**
- Idempotency policy: **TBD**

No product endpoint should be considered stable until it is added to this
document and covered by tests.

## 2. Implemented endpoints

### `GET /api/health`

Liveness check. It confirms that the API process is running. It does **not**
check the database, blockchain connectivity, provider health, or custody state.

**Authentication:** none

**Response: `200 OK`**

```json
{
  "status": "ok",
  "service": "carry-os-api",
  "version": "0.1.0",
  "timestamp": "2026-11-06T12:00:00.000Z"
}
```

The response is validated against `healthResponseSchema` in
`packages/shared/src/health.ts`.

## 5. CORS

The API allows browser origins configured through `WEB_ORIGIN`, a
comma-separated list. The default is `http://localhost:3000`.

## 6. Error handling

A consistent error format, correlation IDs, retry semantics, and rate-limit
responses are **TBD**. Errors must not expose secrets, stack traces, or sensitive
session details.

## 7. Security

The API currently has no authentication or authorization. Do not expose it as a
public production service. See [SECURITY.md](SECURITY.md) for the security
baseline and unresolved controls.
